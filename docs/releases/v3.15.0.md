Release v3.15.0. Powercor's Residential CER two-way tariff (PRCER) gets import and export sensors, priced from a library-extension table until aemo-to-tariff carries the tariff.

## A tariff the library does not carry yet

Powercor's opt-in Residential CER tariff is live for 2026-27 and is not in aemo-to-tariff 0.7.27 or on the library's master branch. Since v3.12.0 the catalogue is the library's, so a Powercor customer on PRCER had no sensor and nothing in the integration could add one (#170).

`tariff_extensions.py` carries such a tariff in the library's own conventions: interval-end lookup with the five-minute step back, c/kWh network rates, GST exclusive where the library's module for the network is, and on the feed-in side a credit positive and a charge negative. PRCER, from the Powercor 2026-27 Tariff Summary (7 May 2026): peak import 27.86 c/kWh December to February and June to August and 20.80 c/kWh March to May and September to November, both 16:00 to 21:00; saver 1.00 c/kWh 11:00 to 16:00; off-peak 4.20 c/kWh otherwise; a 7 c/kWh export credit 16:00 to 21:00 in the peak-season months and a 1 c/kWh export charge 11:00 to 16:00 September to May; 43.84 c/day fixed. The 1 kWh/day free export allowance on the charge is a daily quantity and is not modelled per interval.

The catalogue appends an extension code after the library's codes (so a region's default tariff cannot move), names it, and pairs its export side under the existing same-code rule. The library wins: once an installed release carries the code the entry is inert and one log line says it can be deleted. The five library calls in the tariff sensors go through a routing wrapper for such a code; nothing changes for a library tariff. Every tariff sensor now publishes `tariff_source` (`aemo-to-tariff` or `nem_pd7day extension`), an extension tariff's `tariff_periods` follow the season, and an extension export sensor publishes `export_periods`, the credit and charge windows in force this month (PR #172).

The same tariff is on the purcell-lab fork of the library (branch `powercor-prcer`) for an upstream pull request; when that ships and the manifest floor moves past it, the entry here goes.

## What to expect on deploy

- VIC1 entries gain `sensor.nem_pd7day_vic1_powercor_residential_cer_tariff_prcer` and its export companion, registered disabled because the tariff is opt-in on Powercor; enable them in the entity registry to use them.
- Every tariff sensor gains a `tariff_source` attribute. No published value moves.

Found on the way and filed as #171, not changed here: `daily_supply_charge_$` publishes the library's cents-per-day figure under a dollar name on every tariff sensor.
