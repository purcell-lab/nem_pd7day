Release v3.17.1. The tariff sensors read the additional usage fee from the number entity Home Assistant actually created.

## The fee number was never found

Every tariff sensor adds the region's additional usage fee before GST, read from the region's "Additional Usage Fees" number entity. The lookup built the entity id as `number.nem_pd7day_<region>_additional_usage_fee`, but Home Assistant derives the id from the entity's name, so every install has `..._additional_usage_fees`. The lookup found nothing and every tariff sensor priced with the 0.0293 $/kWh default, whatever the number was set to. On the live install on 26 September, QLD1's number was 0.0224 and its tariff sensors reported and priced with 0.0293 (#181).

The tariff sensors now resolve the number through the entity registry by its unique id, which also follows an entity the user has renamed, and fall back to the derived id, then the old spelling, then the default. The two tariff classes share one implementation in place of two copies, and the tariff description names the right entity (PR #184).

The golden master (v3.17.0 carried its harness) had been hiding this: it served the fee at the id the sensors constructed. It now serves the fee only where Home Assistant would, with an entity registry, and asserts that every tariff sensor reports its scenario's fee. The deliberate snapshot update moves each tariff value by exactly (scenario fee − 0.0293) × 1.1 and nothing else.

## What to expect on deploy

- If a region's usage fee is set to anything other than 0.0293, its import tariff prices move by (fee − 0.0293) × 1.1 $/kWh, and `additional_usage_fee_$/kwh` shows the set value. On QLD1 at 0.0224 every import tariff drops by 0.00759 $/kWh.
- Regions left at the default do not move. No export price moves. No entity is added, removed or renamed.
