Release v3.19.0. aemo-to-tariff 0.7.28, pinned exactly, prices Energex 94300 properly and carries Powercor PRCER; `daily_supply_charge_$` is published in dollars.

## Energex 94300 priced as spot plus network (#165)

aemo-to-tariff 0.7.27 looked Energex codes up by their first four digits, so 94300 (Large TOU Energy) matched nothing and fell to the library's `spot * slope + intercept` guess. That guess did not move one for one with spot and carried no time-of-use windows. 0.7.28 looks the full code up first (PR #203). 94300 is now spot plus its own network rate, with its windows in `tariff_periods` and its daily fee. Energex 94000 (Large Dynamic Flex Storage) is new in the library and gets a sensor, registered disabled.

A new test holds every catalogue import tariff to a price that rises by exactly the spot component. It fails on 0.7.27 with `energex/94300: slope 1.0379`.

## Powercor PRCER moves to the library

0.7.28 publishes PRCER with the rates that `tariff_extensions.py` carried since v3.15.0 (#170). Over a year of intervals the import and export prices agree to the cent, and the daily fee is the same. The extension entry is removed and `tariff_source` reads `aemo-to-tariff`. The seasonal peak windows still follow the date, and the export sensor keeps `export_periods`, which is now read from the library's month-gated feed-in table.

The library's period rows are now asked for at the sensor's time rather than the wall clock's, so the price year and a seasonal tariff's season follow the interval.

## `daily_supply_charge_$` in dollars per day (#171)

The attribute passed the library's cents per day through under a `$` name: Energex 6900 published 65.1 where it meant 0.651 $/day. It is now divided by 100 (PR #204). **Anything that multiplies this attribute up, on a dashboard or in a template, should drop that factor.**

## The library version is pinned (#167)

`manifest.json` now requires `aemo-to-tariff==0.7.28`, the version the tests run against, rather than a floor. The GST correction from #158 restates how the pinned library treats each network, and upstream is moving networks to GST inclusive rates. A floor let Home Assistant install a release CI had never seen, and a migrated network would quietly double count GST again. A scheduled job now runs the library probes against the newest release daily at 06:17 AEST and opens an issue if they fail (PR #205).

## What to expect on deploy

- Home Assistant installs aemo-to-tariff 0.7.28 on restart. Every tariff sensor's `library_version` reads 0.7.28.
- Energex 94300 changes value and gains its periods and daily fee. `sensor.*_energex_94000_tariff` appears, disabled.
- PRCER prices, periods and export windows are unchanged; only `tariff_source` changes.
- `daily_supply_charge_$` drops by a factor of 100 on every tariff sensor.
- No other published value moves.

## Minor

A dependency bump that adds a tariff sensor, and an attribute unit correction.
