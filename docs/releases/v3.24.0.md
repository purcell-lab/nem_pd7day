Release v3.24.0. A two-way tariff's export side is now forecast beyond the Amber horizon: Energex 96200 can be the active tariff, and the active tariff gains a Day 2-7 export tariff sensor. Pre-dispatch tells a link pinned at a flow apart from one that is closed.

## Energex 96200 and a Day 2-7 export tariff sensor (PR #245)

A days 2-7 sensor exists to be summed with an Amber forecast; a days 1-7 sensor overlaps it and counts every interval Amber covers twice. Before this release a customer on Energex 96200 (Residential Two-Way Tariff Trial) had no day 2-7 import sensor, because the tariff could not be selected, and no tariff had a day 2-7 export sensor at all. Amber's feed-in forecast carries no network export charge or reward, so beyond its horizon the only source for one was the overlapping days 1-7 sensor.

- **96200 is selectable** as the active tariff, beside the other networks' trials. The QLD1 default stays 6900.
- **Day 2-7 export tariff sensor.** In days 2-7 mode the active tariff also gets a day 2-7 sensor for its export partner, the same pairing the full export sensors use. It starts where the Amber forecast ends (#235), as the day 2-7 import sensor does, and carries `forecast_start` and `forecast_start_source`. For 96200 it is `Day 2-7 Energex Residential Two-Way Tariff Trial Export Tariff (96200X)`:
  - a charge of 2.21 c/kWh from 11:00 to 13:00, April to October;
  - a reward of 12.195 c/kWh from 17:00 to 20:00, November to March.
- The 96200 tariff sensors are now enabled by default on new installs.

## Pre-dispatch `bound`: `pinned` (PR #244, #243)

`bound` read `closed` whenever an interconnector's export and import limits met. On 13 October Murraylink read `closed` in 19 of 40 periods while carrying 71 to 89 MW, held there by `V^SML_BUDP_3`. Now:

- `closed`: the limits meet at 0 MW, so nothing can flow (NSW1-SA1 before it enters service);
- `pinned`: they meet at any other flow, so the link carries exactly that flow. `limit_constraint` names the constraint holding it.

Only the attribute changes; nothing else in the integration reads it.

## Upgrade notes

- **New entity**: in days 2-7 mode, one Day 2-7 export tariff sensor for the active tariff's export partner, enabled, diagnostic category (for example QLD1 6900 gets 6900X, NSW1 EA025 gets EA029). Nothing is removed or renamed.
- **Option**: Energex 96200 appears in the active tariff list.
- **Values**: no existing value moves. The Murraylink pre-dispatch sensors read `pinned` where they read `closed`.
- **Requirements**: unchanged (`aemo-to-tariff` 0.7.28).

## Minor

A new sensor and a newly selectable tariff, so a minor version. Suite goes from 1724 to 1743 tests.
