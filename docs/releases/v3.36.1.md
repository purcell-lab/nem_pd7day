Release v3.36.1. The integration loads where matplotlib cannot be installed, such as HA-OCPP on Python 3.14, and the DUID and node sensors are named by station first.

## matplotlib is optional (PR #295)

On an install with no matplotlib wheel for its Python, pip fell back to a source build that failed, and because matplotlib was a manifest requirement, the whole integration failed to load.

- **Manifest:** matplotlib is no longer a requirement.
- **Cameras:** they ask Home Assistant's installer for it once per run, in the background, before rendering.
  - **Already installed, or installable:** the charts render as before.
  - **Not installable:** one warning is logged and the cameras show their placeholder image. Every sensor works.
- **Logging:** the chart modules' per-render "matplotlib not available" warnings are now debug.
- **Type-check baseline:** lowered to 34 (#296).

## Station names (PR #297)

The DUID and node sensors were named by code alone; they now lead with the catalogue's name, as the options list shows them:

| Before | After |
|---|---|
| `GSTONE1 Local Price Adjustment` | `Gladstone (GSTONE1) Local Price Adjustment` |
| `QWIV1 Node Price` | `Wivenhoe (QWIV1) Node Price` |

A DUID or node with no other name keeps the code alone.

## Upgrade notes

- **Entity IDs:** unchanged, for existing and new sensors. Only friendly names change, and a name set in HA still wins.
- **Requirements:** matplotlib removed from the manifest.

## Patch

A load fix and a naming change, so a patch version. The suite goes from 1913 to 1921 tests.
