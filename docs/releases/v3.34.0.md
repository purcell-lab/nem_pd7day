Release v3.34.0. A DUID sensor reads 0, not unknown, when AEMO publishes no adjustment for it, and the DUID catalogue's station names read better.

## No row is 0, flagged (PR #283)

AEMO publishes a LOCAL_PRICE row only where a unit's adjustment is not zero, so the DUID sensors were unknown for every unconstrained interval. That left gaps in history and statistics, gave HAEO nothing, and blanked `local_price`.

- **State:** no row for the DUID in a fresh DispatchIS file that has the LOCAL_PRICE table reads **0**, with `row_status: zero_by_omission`, so an inferred 0 stays distinct from a published one.
- **Local price:** with an inferred 0, `local_price` is the region's ROP.
- **Still unknown:** a stale file, one without the table, or no file yet.
- **Forecast:** an interval without a row in a P5MIN run that has the table is 0, listed in `inferred_zero_times` (with a count in `intervals_inferred_zero`). The forecast now covers the run to its last interval.
  - It still stops at a conflicting interval.
  - A stale run, or one without the table, gives no points.
  - Nothing is carried past the run's last interval.

## Station names (PR #283)

- **Acronyms:** AEMO's capitalised names keep their acronyms and codes when title-cased: "Orana BESS", "Terang BESS", "Mt Piper".
- **Internal labels:** where AEMO's only name is an internal label (ASGENE01), the options list shows the DUID once.

## Upgrade notes

- **State values:** DUID sensors that read unknown for unconstrained intervals now read 0. Templates or automations that test for `unknown` should test `row_status` instead.
- **Attributes:** `row_status` and `forecast_status` read `zero_by_omission` where they read `absent`. `inferred_zero_times` and `intervals_inferred_zero` are new.
- **Requirements:** unchanged.

## Minor

A change to published values, so a minor version. The suite goes from 1886 to 1889 tests.
