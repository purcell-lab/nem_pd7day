Release v3.6.0. The usual two files, `manifest.json` and the `README.md` version history row.

One PR since v3.5.0: #111, addressing the twelve issues filed from the full repository review of v3.5.0 (#97, #100 to #110). Every claim in those issues was verified against the code before anything changed. Suite goes from 931 to 1003 tests, green on Python 3.11 and 3.13.

## One change moves published values

The stage 1 quantile regression fitted expectiles, not quantiles. Its IRLS weights depended only on the sign of the residual, which is asymmetric least squares; on right skewed prices about a quarter of actuals fell below the line published as P10. The weight now carries the 1/|r| divisor, `IRLS_EPS` moves from 1e-8 to 1e-4, `IRLS_ITER` from 15 to 100 with a stop on the pinball objective, and the fit uses the same decay weights as the point estimate. Stage 1 P10 and P50 lines move on every install, P10 downward, on the next engine fit. Stage 2 bands and all point estimates are unchanged (#103).

## Two fixes to a running install

The dispatch poll timer could not be cancelled on unload, so every reload of any region entry started another poller beside the orphaned one, each hitting AEMO every five minutes. The coordinator now owns its one pending timer and shuts it down on unload (#101). This takes effect on the restart that installs this release; if the instance has been reloaded since its last restart, that restart also retires the extra pollers.

Two clients sent `nem_pd7day/2.3` as User-Agent and the DispatchIS fallback sent none at all. Every NEMWEB request now carries the browser-like header from `const.py` (#102).

## New published attributes

`band_source` now reaches the `*_pd7day_data` sensor, the one carrying the full forecast array (#100).

After a failed fetch the forecast and tariff sensors keep serving the last good result, as before, but now say so: `data_age_hours`, `is_stale` and `stale_reason` on every forecast and tariff sensor. Availability is unchanged; an automation that wants to refuse stale data can guard on `is_stale`. The opt-in availability threshold discussed in #105 is not in this release and that issue stays open for it.

## Everything else

`strings.json` `unknown` error loses its em dash (#97). SETTLEMENTDATE parsing is one helper for both source formats and a parse failure is logged as a parse failure rather than as stale data (#104). Publish-time fetches use a scheduler holding one timer per slot instead of adding three dead cancels a day to the unload list; every task is tied to its entry or entity; a region's STPASA store is de-registered when its own entry unloads (#106). Twelve inline timezone rebuilds use the canonical `NEM_TZ` (#108). Clock reads go through `dt_util` or an injected clock (#109). Three small calibration cleanups (#110).

CI: Python 3.13, pinned toolchains, `pytest.ini` with asyncio auto mode and RuntimeWarning as an error, a mypy ratchet at a baseline of 79 where the old step had been checking nothing, ruff with every finding fixed, and a version lockstep check that refuses to publish a release whose tag, manifest and README row disagree (#107).

## Minor rather than patch

Published stage 1 bands move and four new attributes appear.

## Not in this release

The #105 availability threshold, left for its own decision. No sensors added or removed, no entity ids changed, no tariff definitions and no runtime requirements changed.
