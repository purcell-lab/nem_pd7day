Release v3.13.0. GST is applied once to the network component of an import tariff, not twice, which lowers every QLD1, NSW1 and SA1 import tariff by a tenth of its network rate; and three fixes found deploying v3.12.0, one of which left a config entry unloadable on Home Assistant 2026.9.

## GST was charged twice on the network component

`aemo_to_tariff` composes a recognised tariff as spot plus network rate in c/kWh. Seven of its thirteen distributor modules gross the network rate up by 1.1 themselves (energex, ergon, ausgrid, endeavour, essential, evoenergy, sapn) and six do not, so the library's return mixes a GST-exclusive spot component with a network component that is GST-inclusive on some networks and not others. `tariff_sensor.py` multiplied the whole result by 1.1, so on those seven the network component carried 21 per cent rather than 10. Measured on the live install at 20:28 on 18 September, Energex 6900 published 0.365616 $/kWh in the evening peak against a correct 0.344130, overstated by 0.021486 $/kWh or 6.24 per cent; the evening-peak overstatement runs from 0.59 c/kWh on Ausgrid EA025 to 3.96 on SAPN (#158, PR #162).

`_retail_price` now splits the library result using the library's own spot formula, removes the library's GST from the network component only where the library applied it, and grosses the total up once over spot, network and the usage fee. The loss factors are passed to `spot_to_tariff` explicitly at both call sites so the decomposition cannot drift from what the library used. The export path is untouched: feed-in tariffs carry no GST and the library adds none inside its feed-in conversion, which a test now asserts. `tests/test_tariff_gst.py` probes every import tariff the installed library publishes against the rates in the library's own tables and fails if a network changes its GST treatment, a new network appears unclassified, or a network becomes mixed across its own tariffs.

## Catalogue order moved SA1's default tariff

The day 2 to 7 tariff sensor and the config flow default to the first default-enabled code in catalogue order when no active tariff is set. v3.12.0 made that the library's table order, and SA Power Networks lists RTOU before RESELE, so SA1's default moved from RESELE to RTOU on deploy: the entity the install was using went unavailable and a new one appeared. `import_tariff_codes` now keeps the snapshot's order for the codes both have and appends the library's new codes, so a library release can only add sensors, never move a default (#159, PR #163).

## Unloading an entry raised TypeError on Home Assistant 2026.9

`entry.async_on_unload` was registered with a lambda that returned the popped `StpasaStore`. Home Assistant 2026.9 schedules whatever an on-unload callback returns as a task, so every unload raised "TypeError: a coroutine was expected" and left the entry in `failed_unload` with all its sensors unavailable; on the live install QLD1 went down at 21:02 on 18 September after a reload and came back with a restart. The callback is now a function returning None, and the lifecycle test pins that shape (PR #163).

## The library requirement was unpinned

`manifest.json` required `aemo-to-tariff` with no version, so an install kept whatever version it first installed and the runtime catalogue introduced in v3.12.0 could not follow a library release; on the live install only one of the 25 new codes appeared. The requirement is now `aemo-to-tariff>=0.7.27`, the version the fallback snapshot and the tests are measured against. Home Assistant upgrades the package at the next start when the floor rises, so a library release reaches an install when the integration raises the floor, and the catalogue then follows without further edits (PR #163).

## What to expect on deploy

- Every import tariff entity on QLD1, NSW1 and SA1 drops by a tenth of its network rate, roughly 0.6 to 4.0 c/kWh depending on network and period. VIC1 and TAS1 do not move. No export entity moves.
- The first start installs aemo-to-tariff 0.7.27 or newer; the disabled-by-default import tariff entities described in v3.12.0 then appear on the networks that were missing them.
- SA1's day 2 to 7 tariff sensor returns to RESELE; the RTOU one created by v3.12.0 is orphaned and can be deleted from the entity registry.
- Reloading or removing a config entry works again.

No entity ids or names change. Suite goes from 1092 to 1164 tests.

## Minor rather than patch

Published tariff values move.
