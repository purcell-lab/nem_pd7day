Release v3.32.0. The tariff Amber reports becomes the active tariff, and only its sensors stay enabled. Opt-in sensors publish a DUID's local price adjustment, now and for the next hour.

## Active tariff from Amber; only the active tariff's sensors enabled (PR #276, #260)

- **Active tariff**, in this order:
  1. the `active_tariff` option, when one is chosen;
  2. the tariff the Amber Express site sensor reports: its `network` is mapped to a distributor of the region, and the `general` channel's `tariff` is used when the tariff catalogue knows it;
  3. the region's default.
- **The new Automatic choice** is labelled with the tariff Amber reports.
- **Export tariff:** Amber's `feedIn` channel reports the import code, so the export partner comes from the catalogue.
- **Only the active tariff's sensors** (`only_active_tariff`, on by default):
  - The other tariffs' default-enabled sensors are disabled by the integration, once each.
  - A sensor you enabled yourself, or re-enable afterwards, is left alone.
  - Turning the option off restores what it disabled.
  - Nothing is disabled when the tariff is only the region's default.
- **Stale day 2-7 sensors** of a tariff that is no longer active are removed.
- **Amber loading after this integration:** the entry reloads once if the Amber site reports a different tariff.

## DUID local price adjustment sensors (PR #277, #275)

Opt in: list DUIDs in the options, for example `GSTONE1, CATHROCK`. For each DUID:

- **`..._local_price_adjustment`**: the latest dispatch `LOCAL_PRICE_ADJUSTMENT` in $/kWh, with `adjustment_mwh`. It comes from the DispatchIS file already fetched for binding constraints, so it costs no extra request.
- **`..._local_price_adjustment_forecast`**: the newest P5MIN run as `forecast: [{time, value}]`. `time` is the interval start in AEST. The list covers the intervals still to end and stops at the first interval without a row.
- **`..._local_price`**, with the diagnostic option: clip(ROP + adjustment, floor, cap) for the entry's region. It is not a regional, retail or settlement price.

An absent row is unknown, not zero. `row_status` tells absent, missing table, stale, expired and conflicting rows apart.

P5MIN is one shared fetch, made only while some entry lists a DUID: a 16 KB listing per dispatch poll, and the 210 KB zip once per new run, parsed in the executor.

## Upgrade notes

- **Tariff sensors are disabled on upgrade.** Where the active tariff is chosen in the options or reported by Amber, the region's other default-enabled tariff sensors are disabled when 3.32.0 loads. On a QLD1 install on Energex 96200 that is the 6900 and 8900 pairs and the default Ergon tariffs. Check dashboards and automations that use them. Re-enable them one at a time, which sticks, or all at once by turning off **Enable only the active tariff's sensors**.
- **DUID sensors:** none are added until DUIDs are configured. With none configured, P5MIN is never fetched.
- **Values:** spot, calibrated, tariff and scarcity values are unchanged.
- **Requirements:** unchanged (`aemo-to-tariff` 0.7.28).
