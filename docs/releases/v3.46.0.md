Release v3.46.0: the tariff sensors on the price timeline, stage 5b of the forecast timeline plan (#333, #339). Every tariff sensor's `forecast` (import, export, and their day 2-7 forms) is now the region's price timeline from the current interval, priced: the dispatch price, P5MIN's 5-minute prices for the next hour, pre-dispatch to the end of the next trading day, then the calibrated PD7DAY spot. These are the same intervals the spot forecast sensor lists since v3.45.0.

## The tariff `forecast`

- **From now:** intervals that have ended are no longer listed. Before, the list started at the PD7DAY run's first interval.
- **Each entry:** it keeps `time`, `nemtime`, `spot_raw`, `spot`, `value`, `period` and `network_rate`, and adds `source` and `resolution_minutes`.
  - For `dispatch`, `p5min` and `predispatch` entries, `spot_raw` and `spot` are the price itself.
  - For `pd7day` entries, `spot` is the calibrated spot, as before.
  - The tariff is applied to each entry's `nemtime`, the interval end, as it always was. For a 5-minute entry, the time-of-use lookup is the interval start.
- **PD7DAY is priced as before.** In the regenerated golden snapshots, all 15,469 `pd7day` entries across every tariff sensor have the same `spot`, `spot_raw`, `value`, `period` and `network_rate` as the entry for the same interval in v3.45.0.
- **Day 2-7:** from where Amber's forecast ends, or by the clock, as before. Pre-dispatch fills any part of the window it reaches.
- **State:** unchanged. `native_value` is still the dispatch price, tariffed.

## Cost

- **Prices are kept.** Each tariff keeps its price per interval while the PD7DAY run, the calibration and the usage fee hold, so a new timeline every 5 minutes prices only its near-term entries.
- **Benchmark** (`bench_updates.py`, attribute build per write):

  | Sensor | v3.45.0 | v3.46.0 |
  |---|---|---|
  | Import tariff | 1.13 ms | 0.31 ms |
  | Export tariff | 0.81 ms | 0.29 ms |

- **No calibration on the event loop:**
  - A tariff write that finds the region's calibrated forecast stale now waits for the forecast sensors' off-loop warm to publish it. That happens on a new PD7DAY run, a refit or an STPASA refetch.
  - Before, the first tariff write after a new run calibrated the whole run on the event loop.
  - The wait is at most 60 seconds. After that, with no warm coming (every forecast sensor of the region disabled), the tariff calibrates through the spot view as before.
  - Unchanged: a tariff's first write when it is added at startup does not wait. If the memo is still cold then, it builds the region's spot map on the loop, once per region, as before.
- **Code moves:**
  - The list building moves to a new service module, `tariff_forecast.py`.
  - The memo-wait moves to a mixin.
  - `TariffEntityBase` goes from 15 methods (the size limit) to 13.
  - The timeline helpers move from `sensor.py` to `region_timeline.py`.

## Upgrade notes

- **Templates and automations** reading a tariff's `forecast`:
  - The first entry is the current interval.
  - Entries are 5 or 30 minutes long; read `resolution_minutes` or `time`/`nemtime` rather than assume 30.
- **Golden snapshots:** regenerated. Only the tariff sensors' `forecast` attributes change. All 522 day 1-7 tariff forecasts list exactly the spot forecast sensor's intervals.
- **Requirements:** unchanged.

## Minor

Published attributes change. The suite goes from 2067 to 2080 tests.
