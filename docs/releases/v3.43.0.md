Release v3.43.0: the forecast hub, stage 2 of the forecast timeline plan (#333, #336). The DUID, node and zone sensors read their P5MIN and pre-dispatch series from one shared hub instead of rebuilding them on every write. Published values are unchanged.

## The forecast hub (PR #354)

- **Before:** every DUID, node and zone sensor rebuilt its P5MIN and pre-dispatch series from the raw run on every state write. The same DUID's series was rebuilt in its DUID sensor, again in a node's sensor, and again in each zone it belongs to. #331 kept one zone's pre-dispatch series per sensor.
- **Now:** one hub per install keeps each series under the run's identity, the call's arguments, the first interval or period end still ahead, and whether the run is stale. Those are the only ways the clock enters a series. Every sensor and every write within an interval reads the same result, and a new run replaces it. The hub replaces the #331 per-sensor memo.
- **Measured:** the warm attribute build per write, `scripts/bench_updates.py` on the `nsw_local_prices` scenario, worst entity of each class:

  | Sensor | Before (ms) | After (ms) |
  |---|---|---|
  | Zone | 0.37 | 0.07 |
  | DUID | 0.30 | 0.03 |
  | Node | 0.35 | 0.04 |

  Writes per poll are unchanged.
- **Values:** the hub calls the same functions the sensors called before. A test compares hub and direct results minute by minute across a real P5MIN run and a real pre-dispatch run, through to stale, and the golden snapshots are unchanged.
