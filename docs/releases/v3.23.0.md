Release v3.23.0. New sensors from AEMO's 30-minute pre-dispatch show, period by period, which interconnectors and network constraints are forecast to bind, and the NSW1-SA1 link (Project EnergyConnect) now has sensors in NSW1 and SA1.

## Pre-dispatch interconnectors and binding constraints (PR #239)

Whether a price spike in one region reaches the next depends on the interconnector between them: a link held at a limit separates the two prices, one that is not passes the spike through. Until now that was visible only from PD7DAY, published two or three times a day, and binding constraints only for the current dispatch interval.

New per-region sensors read NEMWEB `PredispatchIS_Reports`, refreshed every half hour, for each period to the end of the next trading day:

- **Predispatch Interconnector {id}**, one per interconnector in the region's map. State: the current period's flow in MW, in the nominal direction. Attributes:
  - `exportlimit` and `importlimit`, and the constraint setting each;
  - `marginalvalue` and `violationdegree`;
  - `bound` (`export`, `import`, `closed` or `null`) and the `limit_constraint` holding the flow;
  - `rrp_from` and `rrp_to`, the pre-dispatch price at each end;
  - `forecast` per period (not recorded).
- **Predispatch Binding Constraints**. State: the network constraints forecast to bind in the region in the current period, FCAS not counted. Attributes:
  - `max_marginal_value_mwh`;
  - the current period's `constraints` (not recorded);
  - `forecast` per period, with `count`, `max_marginal_value_mwh`, up to five constraint IDs and the price (not recorded).

Example, the 06:01 run of 13 October: at 11:00, QNI was held at its import limit and QLD settled at $148 against NSW's $167. At 18:00 it flowed 728 MW against a 1,179 MW limit, not bound, and QLD's $986 followed NSW's $1,079.

How it behaves:

- **Flow counted as bound:** within the larger of 1 MW and 0.5 % of a limit. Pre-dispatch often reports a zero marginal value for a link held at a frequency-control limit, so the marginal value cannot be used.
- **Penalty values:** marginal values of $1,000,000/MWh or more are constraint-violation penalties. They are listed and counted, but left out of `max_marginal_value_mwh`.
- **Stale runs:** both sensors go unavailable when the run held is more than 75 minutes old.
- **Network load:** one shared coordinator, checked after each dispatch poll, reads the listing only once its run is 30 minutes old. A run is about 800 KB zipped, roughly 38 MB a day.

## NSW1-SA1, Project EnergyConnect (PR #240)

`NSW1-SA1` is published in PD7DAY, PredispatchIS and DispatchIS but was in no region's map. It is now mapped to NSW1 and SA1, nominal direction NSW to SA, so both regions gain `Interconnector NSW1-SA1` (PD7DAY) and `Predispatch Interconnector NSW1-SA1` sensors.

Until the link enters service AEMO holds it at 0 MW with both limits at 0. The spike gate treats a mapped link with no import capability as shut, which would have marked NSW1 and SA1 network-tight whenever they import. A link held at 0 MW both ways for a **whole run** is now left out as not in service; one closed for only part of a run still counts as shut, as an outage would. Pre-dispatch reports such a link with `bound: closed`.

## Upgrade notes

- **New entities**: per region, one `Predispatch Interconnector` sensor per interconnector and one `Predispatch Binding Constraints` sensor; in NSW1 and SA1, `Interconnector NSW1-SA1` and `Predispatch Interconnector NSW1-SA1`. Nothing is removed or renamed, and no option changes.
- **Values**: no existing value moves. The spike gate's output in NSW1 and SA1 is unchanged.
- **Network**: about 38 MB a day more from NEMWEB, shared across regions.
- **Requirements**: unchanged (`aemo-to-tariff` 0.7.28).
- **Docs**: the README region table lists NSW1-SA1, and VIC1's `SA1-VIC1` is corrected to `V-SA`, the ID the code uses.
