Release v3.25.0. The calibration sensor now shows how much data holds up the ends of each isotonic map, so the thin top step behind #247 can be measured on live data before any fix to fitted values is chosen.

## Isotonic end steps in the calibration summary (PR #248, #247)

Stage 1 calibrates each bucket with an isotonic map: a staircase of levels, each the decay-weighted mean of the training rows pooled into it. Beyond the highest training forecast the top level is served flat. When that top step holds only a few recent rows, often from a single day, their mean sets the calibrated value for every high forecast in the bucket. That is the shape #247 reports.

Each bucket in the calibration sensor's `summary` attribute gains:

- `iso_top`: the map's top step;
- `iso_bottom`: its bottom step.

Each is either `null` (no isotonic map in the bucket) or holds:

| key | meaning |
|---|---|
| `x_start`, `x_end` | the range of raw forecasts ($/kWh) in the step |
| `level` | the value served across it, and flat beyond the end of the map |
| `n` | training rows in the step |
| `n_eff` | their Kish effective size under the decay weights, (Σw)² / Σw² |

A top step with a small `n_eff`, or a `level` well above `x_end`, marks a bucket where a few fresh rows set the high end of the map.

## Upgrade notes

- **Attributes**: `iso_top` and `iso_bottom` are added to each bucket of the calibration sensor's `summary`. Nothing is removed or renamed.
- **Values**: no forecast, calibration or band value moves. The fitted values are expanded from the same pooled blocks as before.
- **Requirements**: unchanged (`aemo-to-tariff` 0.7.28).
