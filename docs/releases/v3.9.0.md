One PR since v3.8.3: #133, closing #130 and #132. Suite goes from 1026 to 1039 tests.

## The observation log is stored by day

The calibration observation log was one JSON file per region, rewritten in full every time an actual price settled. With the cap raised to 100,000 observations in v3.8.3 that file grows to about 50 MB per region, and a settled interval arrives every half hour, so the old layout was tens of gigabytes a day of writes across five regions to append a few rows.

Observations now live in one file per NEM calendar day of the interval they describe, `.storage/nem_pd7day.<region>.observations.<YYYY-MM-DD>`, with `.storage/nem_pd7day.<region>.observation_segments` listing the days that exist. A settled interval rewrites one day's file, a few hundred kilobytes, through Home Assistant's delayed save so a burst becomes one write. Pruning to `MAX_TOTAL_OBS` drops whole oldest days and deletes their files rather than rewriting what is kept, so the retained count settles up to a day's worth below the cap. The in-memory view is unchanged: one flat list, oldest day first, so the fit, the time-of-day statistics and the chart are untouched.

## Migration

The first start after upgrade splits the existing `observation_log` file into daily files and deletes it once the split is saved, logging one INFO line per region. Installs still carrying the pre-3.0 unscoped `nem_pd7day.observation_log` key are migrated the same way. Nothing is lost: the migration test round-trips every row.

## A dormant bug fixed on the way

The accumulator that averages repeated actuals for one interval held the observation's position in the list. Every prune shifted those positions and nothing rebuilt the index until the next restart, so a second actual for an interval would have updated the wrong row or raised `IndexError` (#132). It never fired because TradingIS supplies one price per interval, but it now holds the observation itself and retires entries for pruned rows.

## What to expect on deploy

A one-off burst of small writes at first start as about 20,000 rows become roughly 20 daily files per region, then far fewer and far smaller writes than before. The README cleanup section lists the new files. No sensors added or removed, no entity ids changed, no attributes, no tariff definitions and no requirements changed. Published prices do not move.
