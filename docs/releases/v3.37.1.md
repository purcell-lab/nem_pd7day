Release v3.37.1. When AEMO publishes a dispatch file without its local price table, the DUID, node and zone sensors take that interval from the five-minute pre-dispatch (P5MIN) run, instead of going unknown.

## P5MIN fallback (PR #303)

- **The gap:** AEMO now and then publishes a DispatchIS file with no LOCAL_PRICE table at all, never an empty one. That happened in 11 of 576 files over 30 and 31 Oct 2026, all early evening; on the 31st it ran from 18:40 to 19:00. Every local-price sensor read unknown for those intervals.
- **The fallback:** the P5MIN run solved for the same interval keeps its table, so its rows now stand in. A DUID with no row reads 0. The base price (ROP) stays the dispatch file's own.
- **Flagged:** these intervals show `row_status: p5min_fallback` (for nodes, `adjustment_status`), with the P5MIN file named in `fallback_source_file`.
- **Accuracy:** P5MIN and dispatch agree closely but not exactly. Of 172 DUID intervals compared on 31 Oct, 118 were within 5% or $5/MWh.
- **Still unknown:** an interval stays unknown, as before, when no P5MIN run covers it or that run lacks the table too.

## Upgrade notes

- **New status and attribute:** the `p5min_fallback` status and the `fallback_source_file` attribute.
- **Requirements:** unchanged.
