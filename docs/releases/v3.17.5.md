Release v3.17.5. The calibrated forecast memo has one owner; nothing published changes.

## One owner for the calibrated forecast memo

The price forecast, day 2-7 forecast and PD7DAY data sensors of a region, and its tariff sensors, all read one memo of the region's calibrated forecast, so the run is calibrated once rather than once per entity (#35). The rules that keep that memo correct had grown across three places: the write mixin that warms it off the event loop and publishes only under a key that is still live (#58, #60, #61, PR #76), methods the forecast sensors borrowed from each other by assignment, and the tariff sensors' own view of it (#62). The day 2-7 forecast sensor also carried a copy of the per-interval builder.

They now live in `calibrated_forecast.py`, a module with no Home Assistant imports: the memo key, reading and publishing the region's slot, the lazy build, the currency check, the guarded warm, and the tariff spot view. The sensors keep the Home Assistant side (the executor hop, the held write tasks and their cancellation on removal) and one per-interval builder (spec 003, PR #195).

## What to expect on deploy

- Every price, forecast entry, attribute, entity id and name is as before. The golden master is identical, and the deploy was compared against the live values of the previous release.
- No stored data changes; the memo is in memory only.
