Release v3.38.0. A DispatchIS file without its LOCAL_PRICE table is AEMO's zero for every unit, not an outage. The fallbacks now cover only a dispatch file that is missing or stale.

## The missing table is a zero (PR #320, fixes #309)

- **What it is:** AEMO leaves the LOCAL_PRICE table out when no unit has an adjustment. It never writes an empty one. On 31 Oct 2026 the table was missing in exactly the intervals where the only network constraints binding were interconnector limits without unit terms (at 18:45, `L_PEC_X_6C_6G_6H_XST`).
- **What v3.37.1 to v3.37.3 did:** they treated the missing table as a gap and filled it from P5MIN, pre-dispatch or the regional price (`p5min_fallback`, `predispatch_fallback`, `rrp_fallback`).
- **Now:** a fresh file without the table reads `row_status: dispatch_zero`. Every DUID, node and zone member is 0, nothing stands in, and `fallback_source_file` is empty. P5MIN and pre-dispatch runs without the table are 0 for every interval, where before they gave no points.

## Fallbacks for a missing or stale file

- **When they apply:** when the newest dispatch file is more than 15 minutes old, or no dispatch file has been read.
- **The order:**
  1. The P5MIN run covering the current interval, `p5min_fallback`, taking its ROP and rows.
  2. Otherwise, the 30-minute pre-dispatch period covering it, `predispatch_fallback`, taking its RRP and rows.
  3. With neither, `stale` or `no_data`, unknown as before.

## Upgrade notes

- **Statuses removed:** `table_missing` and `rrp_fallback` are gone.
- **Status added:** `dispatch_zero`.
- **Automations:** any that match on the removed statuses need updating.
- **Entities and attributes:** unchanged.
- **Requirements:** unchanged.

## Minor

A change to what a status means and which statuses exist, so a minor version. The suite goes from 1958 to 1960 tests.
