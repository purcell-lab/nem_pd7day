Release v3.50.2: the P5MIN wait from v3.50.1 now writes on the event loop (#379). No price, state or entity changes.

## Fixed

**A tariff's fallback write ran on a worker thread.** v3.50.1 (#377) has a tariff wait up to 30 s for the P5MIN run a dispatch poll fetches. When the run lands in time, the tariff writes with it. That path worked on HA-OCPP: the tariffs matched the spot forecast's P5MIN range and wrote within 1 s of it.

When the run was not published within 30 s, the timer's handler ran in the executor, not on the event loop. Home Assistant refuses `async_write_ha_state` from there. On HA-OCPP at 11:16:45 on 3 November that meant:
- 18 `RuntimeError: ... calls async_write_ha_state from a thread other than the event loop` entries, one per tariff sensor;
- each sensor kept its earlier state until the next new run or dispatch tick.

The handler is now a Home Assistant callback, so it runs on the event loop.

The tests could not see this: their stand-in for `homeassistant.core` turned `callback` into a mock. The stubs now supply Home Assistant's own `callback`, and a test asserts the timer's handler carries its mark.
