Release v3.37.2. Two more fallbacks after P5MIN, pre-dispatch and then the regional price, so a dispatch file without its local price table no longer leaves the local price sensors unknown.

## The fallback chain (PR #305)

- **Why:** on 31 Oct 2026 AEMO's DispatchIS files lost their LOCAL_PRICE table from 19:15, and P5MIN's runs lost theirs too from 19:45. With nothing for the v3.37.1 fallback to use, every DUID, node and zone sensor read unknown. Pre-dispatch kept its table.
- **The chain:** for a DispatchIS file without the table, in turn:
  1. **`p5min_fallback`:** the P5MIN run covering the interval.
  2. **`predispatch_fallback`:** the 30-minute pre-dispatch period covering the interval, from a run solved no more than 75 minutes before its end.
  3. **`rrp_fallback`:** no adjustment. The local price is the regional price; a node or zone reads its static price.
- **Base price:** the regional base price (ROP) stays the dispatch file's own throughout.
- **Still unknown:** only a stale file, or none at all.
- **Sensors:** the DUID sensor's `source`, and `fallback_source_file` on every sensor, name what stood in.

## Upgrade notes

- **Status changes:** a fresh file without its table no longer reads `table_missing` on the dispatch sensors. It reads one of the three fallback statuses instead.
- **Requirements:** unchanged.
