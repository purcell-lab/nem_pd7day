## Tariff state writes no longer stall the event loop

Home Assistant logged tariff sensor state updates of 0.4 to 0.9 s on the live install, during normal operation. Profiling a cold tariff write on a 336 interval run, the one that runs inline on the event loop when the calibrated-spot memo has no entry for the current run, STPASA run or fit, put 92 per cent of the time in `PD7DayCoordinator.current_run_features`. `calibrate_interval` reads it once per interval and the property re-parsed every interval's timestamp on each call: 336 x 336, 115,795 parses, to calibrate one run.

The run features are now computed once per run identity, the generated-at stamp and interval count, and reused until either changes. Every caller benefits, since the forecast sensor, the chart camera and the tariff sensors all reach it through `calibrate_interval`. On the benchmark fixture a cold tariff write goes from 191.7 ms to 24.6 ms and a warm write is unchanged at 10.8 ms.

## What to expect on deploy

The slow-update warnings for tariff sensors stop. Nothing published changes: the cached value is the same number the property computed before, so every calibrated price is identical. No sensors added or removed, no entity ids changed, no attributes, no tariff definitions and no requirements changed.
