Release v3.20.0. A Binding Constraints sensor per region, links to each grid notice, scarcity forecast times in NEM time, and a manifest that passes hassfest again.

## Binding constraints (PR #230)

A new sensor per region, `sensor.nem_pd7day_{region}_binding_constraints`, shows the network constraints binding in the latest 5-minute dispatch interval, as [nem.live](https://nem.live/) does. The state is the count for the region; the `constraints` attribute lists each one, largest cost first, with `rhs`, `marginal_value_mwh` ($/MWh), `previous_marginal_value_mwh`, `first_bound` and `bound_minutes_today`. FCAS constraints are listed separately in `fcas_constraints` and not counted. The lists are not saved to the recorder.

- **Source**: NEMWEB DispatchIS, the `DISPATCH,CONSTRAINT` table. Binding means a non-zero marginal value in the pricing run.
- **Regions** are read from the constraint ID following AEMO's Constraint Naming Guidelines, because DispatchIS publishes no region. IDs that follow no documented convention (for example `L_PEC_X_6C_6G_6H`) go in `unassigned_constraints` in every region rather than being guessed.
- **Schedule**: one shared fetch after each dispatch poll, no timer of its own. The price path does not depend on it.
- **History** is held in memory: `first_bound` and `bound_minutes_today` count from `tracked_since`, the first interval seen since Home Assistant started.
- **Unavailable** before the first file and when the latest interval is more than 15 minutes old.

## Grid notice links (PR #229)

Every notice in the `grid_notices` `notices` attribute, and in `grid_stress` `active_notices_7d`, gains `url`: the NEMWEB file it was read from, for example `https://www.nemweb.com.au/REPORTS/CURRENT/Market_Notice/NEMITWEB1_MKTNOTICE_20260929.R145393`. Notices stored before the upgrade get the file named for their creation date, which matched in all 672 notices checked. NEMWEB keeps files in `Current` for about 60 days.

## Scarcity premium times in NEM time (PR #228)

The scarcity premium's `forecast[].time` values are now written in NEM time, `2026-10-07T10:30:00+10:00` rather than `2026-10-07T00:30:00+00:00`. Same instants, same values. Readers that parse the offset, HAEO included, see no change.

## Manifest (PR #225)

`astral` is removed from `requirements`. Home Assistant ships it, and hassfest now rejects custom integrations that list it. The integration still uses it, from Home Assistant's own install.

## Upgrade notes

- **New entities**: one Binding Constraints sensor per configured region. No existing entity is removed or renamed, and no option changes.
- **NEMWEB load**: about two more requests every 5 minutes (about 576 a day, 11 MB), through the shared NEMWEB request gate.
- **Attributes**: notices gain `url`; scarcity `forecast[].time` strings change offset. A template that compared those strings as UTC text would need updating.
- **Requirements**: `astral` no longer listed; nothing new pinned.
- No tuning constants changed: forecasts, calibration and tariffs are unaffected.

## Minor

A new sensor, so a minor version. Suite goes from 1591 to 1638 tests.
