Release v3.36.2. Prices are reported raw, never clipped, and a node sensor's state is the node price including its constraint.

## Raw local prices, constrained node state (PR #299)

At 16:05 on 31 Oct 2026 Gladstone was heavily constrained: GSTONE1's adjustment was −1110.09 $/MWh against a QLD1 ROP of 70.08.

- **No clipping:** the DUID sensor's `local_price` was clipped to the −1000 floor; it is now ROP + adjustment as it is, −1040.01. `price_floor_mwh` and `price_cap_mwh` stay, for reference only.
- **Node state:** `Gladstone (QGLD1) Node Price` read 0.065 $/kWh, because its state was the static price alone. It is now ROP × MLF + the node's adjustment, −1.045 $/kWh then.
  - **Its parts:** `static_price_mwh` (ROP × MLF) and `adjustment_mwh`, alongside `node_price_mwh` (the state in $/MWh).
  - **Forecast:** P5MIN adds each interval's adjustment, as the pre-dispatch forecast already did.

## Upgrade notes

- **Node history:** a node sensor's state changes meaning from this release, from the static price to the node price with its adjustment. For an unconstrained node the two are equal.
- **Removed:** the node sensor's `local_price` and `local_price_mwh` attributes, added in v3.36.0; that value is now the state.
- **Requirements:** unchanged.
