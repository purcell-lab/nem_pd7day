Release v3.11.0. The stage-2 serving gate weighs each out-of-range excursion by the coefficient it multiplies. Published values move on intervals the v3.10.0 gate refused for hairline excursions.

## The range gate refused rows for excursions worth under a cent

v3.10.0 refused stage 2 whenever any feature lay outside its training range. Reconstructed on the live install with the v3.10.1 coefficients, across five regions it refused 141 rows that v3.9.2 would have served, 120 of them on excursions worth under a cent of prediction: `poe_spread_n` a hundredth below a range 0.05 wide, `log_solar` and `log_surplus` a hair past their spring extremes. Only the handful the gate was built for, deep demand troughs and off-the-scale spike compression, were worth refusing. The median lost correction was 0.9 c/kWh, the largest 6.4 c (#153, PR #156).

`OlsModel.serves` now charges each feature |coef| per unit of distance outside its training range, sums the cost, and refuses only when it exceeds half the bucket's residual spread, `(q90 - q10) / 2`: the distance from the point estimate to either edge of the band the bucket already publishes. That allowance is fitted from the same rows as the coefficients, so there is no constant to choose. Inside the ranges the cost is zero and the row is served as before. A bucket with ranges but no usable residual quantiles falls back to the strict range test, and a payload without ranges serves as it did before #147. The #147 case, `log_demand` 2.5 units below its floor at about 0.05 $/kWh per unit, costs several times the allowance and stays refused.

## A date-dependent test

`tests/test_tariff_write_latency.py` hard-coded a 5 September run stamp against a fixture anchored to now, so from 9 September no row lay within 24 h of the stamp and the run features were `None`. The stamp is now derived from the fixture's own run time.

- No new attributes. `summary.stage2` (ranges, coefficients, residual quantiles) is enough to reconstruct the gate for any published row.

No sensors added or removed, no entity ids changed, no tariff definitions and no requirements changed. Suite goes from 1064 to 1067 tests.
