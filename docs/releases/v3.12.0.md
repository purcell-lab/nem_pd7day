Release v3.12.0. Tariff sensors are enumerated from the installed aemo_to_tariff library rather than from hard-coded lists, so a tariff added in a library release appears after the next restart and names follow the library's wording.

## The tariff catalogue was hard-coded and had drifted

Every tariff the integration knew about came from `const.py`; nothing read `aemo_to_tariff`'s own tables at runtime, so a new tariff in the library did nothing until the integration was edited. The friendly-name lookup read a `module.tariffs` attribute the library had replaced with per-financial-year tables behind `get_tariffs()`, so on twelve of thirteen networks it silently fell back to stale constants. Measured against aemo-to-tariff 0.7.27: 25 library import tariffs had no sensor (Ergon's nine business and demand codes, Jemena A100/A130/A200/A210, Powercor ND1/NDD/PRSTOU, United LVM1R/LVTOU/RESKW1R, AusNet NAST12/NEE11/NEE12, TasNetworks TAS22/TAS31, Energex 96200); ten listed codes could not be converted (six retired Ergon codes, and five feed-in codes listed as imports, one of them enabled by default); 41 friendly names differed from the library's (#159, PR #160).

`tariff_catalogue.py` is now the single reader of the library: import codes from `get_tariffs()`, feed-in codes from `get_feed_in_tariffs()`, names from the same tables. The sensor platform and the config flow enumerate from it. A code the library cannot convert is not created; a tariff the library adds appears disabled in the entity registry unless it is in the curated default-enabled set. Export programs stay curated, since the library does not say which import tariff an export program belongs to, and each export code is checked against the network's feed-in table where one is published. The hard-coded lists remain only as the fallback for an install where the library is not importable, regenerated as the 0.7.27 snapshot. The library is now pinned in the test requirements, so the suite exercises the real catalogue; until now the test job had no library at all, which is how a test pinning the stale names kept passing.

## What to expect on deploy

- Entity ids do not change: unique ids are unchanged.
- Friendly names move to the library's wording on about 41 tariffs, e.g. Energex 3900 becomes "Residential TOU Demand & Energy", AusNet NAST11S "Small Residential Time of Use".
- Six retired Ergon import entities (3900, 3600, 3800, 7200, ERTDEMXT1, ERTDEMCT1) and the five feed-in codes (N61, BLNREX2, BLNBEX1, RESELEX, SBELEX) are no longer created as import sensors; they published nothing before. The export sensors for N61, BLNREX2 and RESELE are unaffected. Endeavour N61 leaves the default-enabled set as an import tariff.
- 25 new import tariff entities appear, disabled by default; enable the ones you use in the entity registry.

No requirements changed for the integration itself. Suite goes from 1067 to 1092 tests.

## Minor rather than patch

Entities are added and removed and friendly names change.
