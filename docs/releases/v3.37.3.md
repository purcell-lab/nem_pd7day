Release v3.37.3. A fallback period that AEMO left with no local prices at all no longer counts as a source; the interval goes on to the next fallback.

## Empty periods are not a fallback (PR #307)

- **What happened:** on the evening of 31 Oct 2026, the 20:32 pre-dispatch run had its LOCAL_PRICE table, but rows only from midnight on. No unit in the NEM had a row from 21:00 to 23:30.
- **Why that mattered:** v3.37.2 read the empty period as a 0 adjustment for every unit and labelled the interval `predispatch_fallback`, crediting pre-dispatch with data AEMO hadn't published.
- **The fix:** a P5MIN interval or pre-dispatch period with no row for any unit now falls through to the next fallback, `rrp_fallback` that evening.
- **Values:** unchanged, since the adjustment is 0 either way. Only `row_status` and `fallback_source_file` change.

## Upgrade notes

- **Labels only:** no new entities or attributes; only the status labels change.
- **Requirements:** unchanged.
