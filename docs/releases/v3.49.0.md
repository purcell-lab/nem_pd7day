Release v3.49.0: the clean-up, stage 6 of the forecast timeline plan (#333, #340), and the rest of stage 2 (#336). No published value, state or entity changes: the golden snapshots are unchanged across all three PRs.

## Faster

- **The pre-dispatch constraints sensor:**
  - On a real PredispatchIS run (63 periods, 956 binding constraints), each write took about 10 ms. Nine tenths of that was re-reading every constraint ID of every period with regular expressions. During startup, with calibration warming in the executor, those writes logged 0.40 to 0.55 s slow-write warnings.
  - `describe_constraint` is now kept per ID: it is a pure function returning a frozen value.
  - The sensor's rows are kept in the shared forecast hub per run, dispatch interval and period.
  - A write now takes about 0.6 ms when the rows are rebuilt, and nothing between rebuilds.

## Removed

- **Unread `PD7DayData` summary fields:** `current_value`, `next_value`, `min_24h_value`, `max_24h_value` and `cheapest_2h_window`, with the code that computed them. A forecast cache written by an earlier version still loads; the old keys are ignored.
- **An unreachable branch:** the spot map's "derive from the forecast memo" path. Since v3.46.0 a tariff reads that memo itself and reaches the spot map only when the memo does not hold the run.

## Gates

| Gate | v3.48.0 | v3.49.0 |
|---|---|---|
| mypy | 34 errors counted in CI; 57 once numpy and matplotlib are typed | 0, with them typed in CI; any new error fails CI |
| import-linter | report only, 2 contracts broken | enforced, 2 kept; a test keeps every module in a layer |
| size baseline | 28 functions, 4 classes | 27 functions, 3 classes; seven entries smaller |

- **mypy:** the CI typecheck installs numpy and matplotlib at the test pins (#296), so the chart code is checked rather than `Any`.
- **import-linter:**
  - Imports under `TYPE_CHECKING` are no longer counted as layer dependencies.
  - `shared_dispatch` takes its coordinator factory from the composition root instead of importing it.
  - The constraint and pre-dispatch modules join the layers.
- **Size:**
  - `NemPd7dayTariffSensor`'s time-of-use methods move to a mixin: 17 methods to 12, 322 lines to 225.
  - The chart camera's fallback calibration is split into two functions.

## Docs

`docs/architecture/forecast-timeline.md` describes the architecture: each NEMWEB source is fetched once, the forecast hub builds each run's series once, one price timeline is built per region, and every entity is a view of it. It also covers the rules that keep this cheap, and the one seam stage 3b (#337) plugs into.

## Upgrade notes

Nothing to do. If you downgrade below v3.49.0, the first restart may log a warning that the forecast cache could not be restored, and fetch afresh.
