Release v3.35.0. Static node price sensors for chosen transmission nodes: the region's original price times the node's marginal loss factor, now and for the next hour. Stage 1 of #285.

## Transmission node prices (PR #289)

- **Options:** a new field, *Transmission node prices*, lists the region's connection points (TNIs), labelled with their stations and DUIDs (`QWIV1 · Wivenhoe (W/HOE#1)`). A TNI can also be typed: two to ten letters or digits.
- **Sensor:** each chosen node gets `<TNI> Node Price`, in the Diagnostic category, in $/kWh.
  - **State:** ROP × MLF for the latest dispatch interval, from the DispatchIS file the constraints already read. It is not clipped.
  - **Forecast:** the P5MIN ROP × MLF for each interval still to end.
  - **When it is unknown:** for a stale file, before any file is read, when the file has no ROP for the node's region, or when the TNI is not in the catalogue. `row_status` and `forecast_status` say which.
- **What it means:** the static node price is what a generator connected there is paid per MWh sent out, before any local price adjustment. It is a diagnostic, not the price at your meter.
- **Catalogue:** each DUID's TNI and MLF now come from AEMO's DUDETAILSUMMARY, and DUIDs are grouped into 754 nodes, with coordinates where the units have them. The DUID sensors publish `tni` and `mlf` too.

## Upgrade notes

- **New entities:** none until a node is chosen; there are no presets.
- **Data:** P5MIN is fetched while any DUID or node sensor is enabled.
- **Requirements:** unchanged.
