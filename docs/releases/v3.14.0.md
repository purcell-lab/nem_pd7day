Release v3.14.0. Export tariff sensors are paired from the aemo-to-tariff library's own tables rather than a curated list, so a library release that adds a feed-in tariff adds the sensor; the installed library version is published on every tariff sensor and in diagnostics.

## Export pairings come from the library

`EXPORT_TARIFF_PROGRAMS` was a hand-written list of five import-to-export pairs, so a library release that added a feed-in tariff or a battery pairing added nothing to the integration; Energex 96200, the Residential Two-Way Tariff Trial, arrived in v3.12.0 with no feed-in companion for that reason. `tariff_catalogue.export_programs()` now derives the pairing from the library at startup, three rules in order, each applied only to import codes still unpaired: the same code is both an import tariff and a feed-in tariff (SAPN RESELE, RELE2W, SBELE, B2R; Endeavour N95; Evoenergy 026); the import code with an `X` suffix is a feed-in tariff (Energex 6900X, 6800X, 96200X); or the library's `battery_tariffs()` lists the same number of imports and exports for a customer type, taken positionally (Ausgrid EA025 and EA225 to EA029, Endeavour N71 to N61, Essential BLNRSS2 to BLNREX2 and BLNBSS1 to BLNBEX1).

What the library cannot express goes in `EXPORT_TARIFF_OVERRIDES` in `const.py`, which also wins over a derived pairing for the same import code. It is empty: the one live case is Ergon, which lists NVGC2 and NVGX2 against every import tariff with nothing saying which applies, so Ergon gets no export sensor and `unpaired_export_codes("ergon")` reports both. The old constant is now the no-library fallback, regenerated to what the derivation yields on 0.7.27, and a test keeps the two equal so a library release that adds a pairing fails the suite until the snapshot is refreshed (PR #166).

## The installed library version is visible

After v3.13.0 raised the requirement to `aemo-to-tariff>=0.7.27`, only one of the 25 expected new import codes appeared in the live entity registry, and nothing distinguished a library Home Assistant had not upgraded from a registry that keeps user-deleted entities deleted. `tariff_catalogue.library_version()` reads the package metadata once at import, off the event loop, and is published as `library_version` on every tariff sensor and as `aemo_to_tariff_version` in the config-entry diagnostics (PR #166).

## What to expect on deploy

- Essential's export sensor follows the library's pairing, BLNRSS2 rather than the curated BLNT3AL, so its unique id changes from `..._essential_BLNT3AL_export_tariff` to `..._essential_BLNRSS2_export_tariff`. The old entity is orphaned and can be deleted from the registry.
- New export sensors, enabled by default only where the import tariff is: Energex 6900X, 6800X and 96200X (QLD1); Ausgrid EA225 to EA029, Endeavour N95, Essential BLNBEX1 (NSW1); SAPN RELE2W, SBELE and B2R (SA1).
- Every tariff sensor gains a `library_version` attribute. If it reads below 0.7.27 the install has not picked up the floor and that is the next thing to look at.
- No published value moves. Ergon, VIC1 and TAS1 gain nothing.

Suite goes from 1164 to 1177 tests.

## Minor rather than patch

Entities are added and one unique id changes.
