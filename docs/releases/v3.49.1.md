Release v3.49.1: a leaner PredispatchIS parse (#364). No published value, state or entity changes.

## Faster

Each new pre-dispatch run, every half hour, is unzipped and parsed in the executor. On four real runs (63 to 78 periods, 63,661 to 75,966 constraint rows):

| | v3.49.0 | v3.49.1 |
|---|---|---|
| Parse | 0.7 to 1.5 s | 0.2 to 0.3 s |
| Allocation peak | 106 to 126 MB | 18 to 22 MB |

On a Home Assistant Green, several times slower, the parse was several seconds of executor work a run with a 120 MB spike. It ran during the 3 s slow write seen on HA-OCPP (#363).

What changed:
- **Timestamps:** each period's timestamp is parsed once rather than once a row. A run has about 72 distinct timestamps across some 76,000 rows, and `strptime` was most of the parse.
- **Non-binding constraint rows:** nearly every CONSTRAINT_SOLUTION row is not binding. Those rows are now counted without building a dict each; the first in each period stands for the rest, so the period still has its entry and `evaluated` still counts them.
- **No StringIO copy:** the text is split into lines on "\n", as `StringIO` iteration does, rather than copied into a `StringIO` buffer.

## Same result

A new test parses every real PredispatchIS fixture and a hand-made file with the edge cases, and compares the result with a reference copy of the old parse. The edge cases:
- a period with nothing binding;
- a row cut short;
- an intervention row;
- a bad timestamp;
- a quoted line break.

The four full-size runs above were checked the same way. Golden snapshots are unchanged.
