Release v3.17.4. The tariff sensors are restructured inside; nothing they publish changes.

## Tariff pricing in one module

The rules for turning a spot price into a tariff price used to live inside the tariff sensors, beside the Home Assistant entity code, and the Powercor PRCER extension (#172) had to route every priced call through module-level wrappers to reach them. They now live in `tariff_pricing.py`, a module with no Home Assistant imports: a pricer for tariffs `aemo_to_tariff` carries and one for the PRCER extension table, chosen per tariff; the GST correction from #158, unchanged to the last bit; and the time-of-use window lookup (spec 001, PR #192).

## One base class for the tariff sensors

The import and export tariff sensors shared their half-hour tick, dispatch subscription, availability, usage fee and calibrated spot price by copying code, and the export sensor borrowed three calibration methods from the import sensor by assignment, which is how #66 happened. They now inherit all of it from one base class, the three forecast loops are one, and the day 2-7 sensor overrides only which intervals it lists (spec 002, PR #193).

## Refactor gates in CI

Pull requests now run a line coverage comparison against the base branch, a size ratchet on functions and classes, a check that a `refactor:` pull request leaves the golden-master snapshots untouched, and an import-layer report (spec 000 part C, PR #191). The golden master itself (spec 000 part A) pins every entity's state and attributes across twelve scenarios.

## What to expect on deploy

- Every tariff price, attribute, entity id and name is as before. The golden master is identical, and the deploy was compared against the live values of the previous release.
- No stored data changes.
